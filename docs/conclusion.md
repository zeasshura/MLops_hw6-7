# Единый вывод по ДЗ 6+7

## Протокол закреплён до генерации

Исходная задача ДЗ 4–5 — короткие ответы на вопросы по Wikipedia-пассажам. Для строгой автоматической проверки отложенные вопросы переведены в выбор четырёх вариантов A–D с JSON-ответом. Это изменение формата протокола одинаково для базы и кандидата, но может ухудшить формат у адаптера, обучавшегося короткому текстовому ответу. Критерии не ослабляются при таком результате.

Golden содержит 50 разных пассажей: biology (20), culture (15), geography (15). Все три среза критические: требуется отсутствие ухудшения в каждой предметной области, иначе улучшение среднего могло бы скрыть потерю одной темы. Общий n=50; behavioral оценивается отдельно и не добавляется в общий n. Статьи целиком вне train, точных совпадений и пересечений group_id нет. Темы golden также не входят в фиксированный val-пул из первых восьми примеров Tucson, используемый для выбора по loss.

Выбор вариантов и эталонных меток детерминирован; source содержит исходный ID, статью, текст эталона и позицию в пассаже. В `review.jsonl` сохранены вопрос и подтверждающий контекст для ручной проверки. Вопросы и доказательства проверены ассистентом по источникам, независимая человеческая проверка не заявляется. Тексты исторических исходников оцениваются как чтение предоставленного отрывка, а не как актуальная справочная информация.

Протокол: один system prompt, greedy decoding, seed 42, максимум 24 новых токена, enable_thinking=false. Полностью оцениваются только закреплённая база и один лучший кандидат; остальные пять моделей участвуют только в сравнении по loss. Ревизия базы зафиксирована commit SHA. Три behavioral-кейса: строгий JSON, перефраз вопроса с общей group_id и отказ REFUSE на запрос написания кода вне passage-only задачи.

## Ограничения

Шесть конфигураций имеют одинаковый небольшой бюджет: train-пул 32, val 8, четыре шага, batch 1 × accumulation 2. Это демонстрация воспроизводимого выбора, а не поиск глобально лучшего адаптера. Golden использует отложенную часть своего датасета; он не является независимым аудитом. Автоматическая проверка точных текстов и групп не исключает всех смысловых перефразов. По одному вопросу на пассаж уменьшает зависимость, но вопросы внутри одной статьи всё равно коррелируют.

Сходство слов (BLEU/ROUGE) может наградить неверный ответ с похожей формулировкой и наказать корректный синоним. В этой задаче сравниваются метки, а формат отдельно. LLM-as-judge был бы полезен для свободных объяснений или неоднозначных случаев, но склонен к позиционным и стилевым искажениям и не заменяет проверку источника. Платный API не используется.

Память измерена как RSS всего Python-процесса, а не как размер весов или чистая память одного адаптера. Runs шли последовательно в одном процессе; после валидации MLflow могли сохраняться объекты/буферы и кэш аллокатора. Поэтому различие RSS первого и последующих runs нельзя приписывать только рангу LoRA. Время в таблице включает обучение и оценки val внутри train(), но не всё время упаковки и проверки MLflow-модели.

Фактическая база уже достигла 50/50 правильных JSON-ответов на golden. Это потолочный эффект: данный набор не позволяет доказать улучшение accuracy, только отсутствие обнаруженной регрессии. Межпредметные distractors упрощают выбор. После просмотра результатов набор и пороги не изменялись; для будущего эксперимента полезен отдельный более сложный набор с близкими по смыслу вариантами.

## Измерения и решение

Ниже приведены реальные результаты законченного sweep и оценки. Кандидат отклонён по качеству: accuracy и format rate снизились со 100% до 18%. Отдельные правильные буквы без JSON не соответствуют заранее закреплённому контракту. Порог допуска ухудшения равен нулю и менять его после просмотра результатов нельзя.

Кандидат НЕ принят в champion. Alias candidate сохранён; baseline не изменён. Следующий шаг — изучить проваленные ответы и формат, подготовить новый эксперимент без ослабления текущего gate.
Отрицательный опыт: rejected=True, причина: Несогласованный count: correct.
Дополнительная испорченная копия с согласованными counts и валидным JSON: rejected=True, причина: Регрессия общей метрики accuracy. Исходные ответы не изменены.
Probe пережил пересоздание контейнера: run `9b5c6a002f0a4d6ba962c23381e6c010`, SHA256 `cd2c44e6bf05ca65ef925be029f7f7e4103ed6660737d48f240afd761730a663`.
