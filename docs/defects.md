# Исправления ДЗ 6+7

## 1. Все конфигурации записывались в один run

Исходный sweep создавал единственный дочерний run `all-candidates`, затем обучал в нём все шесть адаптеров. Параметры логировались только при пустом наборе params: последующие модели получали параметры первого кандидата, метрики смешивались, а артефакты могли перезаписываться. Исправление: отдельный nested run внутри цикла для каждого кандидата. Родительский run содержит только итоговую таблицу. Доказательство — шесть разных run_id и совпадение фактических rank/target_modules с параметрами MLflow; реальные ссылки и числа добавляются после sweep.

## 2. Артефакты терялись после замены контейнера

В compose был объявлен volume `artifacts`, но не был смонтирован в сервис MLflow. PostgreSQL сохранял метаданные, однако файлы адаптеров оставались в слое контейнера. Добавлено `artifacts:/mlartifacts`, что совпадает с `--artifacts-destination`. Проверка доказательства записывает случайный probe, пересоздаёт только контейнер MLflow и скачивает probe заново, сверяя SHA-256. База и volumes не удаляются. Отчёт находится в `metrics/storage-check.json` и копии для сдачи.

## 3. Из provenance исключались версии train/val

Функция provenance уже считала SHA-256 двух тензоров, но sweep явно отбрасывал ключи с префиксом `data_`. В результате нельзя было проверить, на каких именно данных выполнены runs, и корректный selector отказывал в выборе. Теперь provenance полностью сохраняется в тегах каждого run. Сохраняются также git SHA, признак dirty, SHA кода и конфига, разрешённая точная ревизия базы. Собственные train/val из ДЗ 4 взяты без перетокенизации. DVC хранит версии тензоров и eval-набора. Полный индекс исходных 15 336 train-вопросов сопоставлен с 15 257 токенизированными строками по ID; 79 строк без supervision отбрасывались ещё в ДЗ 4.

## 4. Регистрация обходила loss-порог

Функция promote вычисляла отношение final_val_loss/base_val_loss, но сразу регистрировала модель, не вызывая уже написанный gate. Плохой или незаконченный run мог получить alias. Теперь `gate(run, threshold)` вызывается до `mlflow.register_model` и любых изменений реестра. Он проверяет статус FINISHED, конечность чисел, положительность base loss, допустимость порога и отношение loss. Alias candidate создаётся после loss-порога. Champion назначается только отдельной командой оценки, которая повторно пересчитывает качество из raw-ответов. Отказ по качеству допустим; пороги не меняются после оценки.

## Реализованные функции оценки

`score` принимает строгий JSON с единственным строковым полем answer из choices; лишние поля, повтор ключа, markdown, NaN, неизвестные метки и не-JSON не считаются валидными. Ошибки генерации сохраняются в per_item и знаменателе. Accuracy, format rate и исходные counts считаются по всему набору и каждому срезу. Отсутствующие, лишние или повторные ID вызывают ошибку контракта.

`quality_gate` проверяет совместимость трёх хешей, полные отчёты и модели, минимум 50 golden-примеров и три среза, согласованность counts с per_item и конечность метрик. Он отказывает при ошибках генерации, снижении общей accuracy/format rate, снижении accuracy критического среза и провале хотя бы одного из минимум трёх behavioral-кейсов. Все обязательные cases остаются в знаменателе. Отрицательный опыт портит копию ответов, исходные ответы, веса и alias остаются прежними.

## Среда и неизменность тестов

Подготовлена CPU-версия окружения с Python 3.12 и точными версиями основных библиотек. В Fedora используется установленный rootless Podman и официальный Docker Compose v2 через прозрачную команду `tools/docker`; это не имитация контейнеров. `.dockerignore` исключает веса, данные и .venv из build context. Старые артефакты ДЗ 5 исключены из текущего Git-индекса без удаления с диска; история предыдущего репозитория сохранена.

Все файлы выданного `tests/` скопированы без изменений. Отпечаток `c42ac7788026`. Модульные тесты scorer/gate и обвязки пройдены: 24/24. Итоговые `make check`/`make check-all` выполняет пользователь для записи видео; их успешность здесь не утверждается.

## Дополнительная ошибка среды: SELinux после пересоздания

Реальная проверка обнаружила особенность Fedora/rootless Podman: probe.txt сохранился физически, но после пересоздания MLflow получил отказ Permission denied. Причина — приватная SELinux-метка файла от старого контейнера (категории c130,c246) при новой метке процесса (c149,c921). Это не потеря данных и не ошибка обучения. Для постоянных volumes PostgreSQL и артефактов добавлен `:Z`: содержимое рекурсивно получает приватную метку нового контейнера при монтировании. SELinux не отключается. Повторная проверка подтвердила совпадение SHA256 после очередного force-recreate. Дополнительно localhost исключён из прокси через NO_PROXY/no_proxy.
